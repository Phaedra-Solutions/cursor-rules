**Правила с учётом версий и приоритетом безопасности для Cursor, Claude Code, OpenAI Codex, GitHub Copilot и Gemini CLI.** Открытый исходный код (MIT), поддерживается [Phaedra Solutions](https://phaedrasolutions.com).

`cursor-rules` — библиотека правил программирования и [Agent Skills](https://agentskills.io), которая заставляет ИИ-агентов работать с вашим стеком как senior-инженер. Прежде чем агент напишет код, каждое правило проверяет, какую версию фреймворка на самом деле использует проект. Затем оно применяет актуальные соглашения, меры безопасности и проверки известных уязвимостей для этой версии. Для старых версий или версий с истёкшей поддержкой (EOL) правило переключается на рекомендации для legacy-кода и путь миграции. Из одного источника собираются правила проекта Cursor (`.mdc`), `AGENTS.md`, `CLAUDE.md` и Agent Skills (`SKILL.md`), поэтому все инструменты вашей команды следуют одним и тем же инструкциям.

## Зачем правила с учётом версий

ИИ-агенты обучены на многолетней смеси примеров, поэтому часто пишут код не под ту версию. Они используют `middleware.ts` в приложении на Next.js 16, NgModules в Angular 22 или `getServerSideProps` там, где используется App Router. А ещё добавляют несуществующие пакеты, пропускают проверки авторизации и копируют шаблоны с известными CVE.

Универсальные файлы правил только усугубляют проблему: они рассчитаны на одну версию, устаревают за несколько месяцев и ничего не говорят о безопасности. Эти правила устроены иначе:

- **Сначала проверяют версию.** Каждое правило стека начинает с чтения установленной версии из lockfile или манифеста и сообщает, какое правило и какую версию применяет.
- **Остаются актуальными.** Каждое правило указывает диапазон версий, для которого оно написано (`applies_to`), свои источники и дату `last_reviewed`. Еженедельная задача отмечает правила, чей диапазон отстал от нового мажорного релиза или даты окончания поддержки.
- **Безопасно работают с legacy-кодом.** Если проект ниже диапазона правила, агент следует правилу из `legacy/`. Он вносит минимальные изменения, сохраняющие поведение, никогда не использует API новее установленных, сообщает статус EOL, добавляет компенсирующие меры для неисправленных CVE и предлагает навык миграции.
- **Встраивают безопасность.** Правила безопасного программирования по OWASP включены всегда. Каждое правило стека добавляет свой раздел о безопасности и датированную таблицу известных уязвимостей.

## Как это работает

Правила и навыки пишутся один раз в `rules/` и `skills/`, а затем собираются для каждого инструмента.

1. **Базовые правила включены всегда.** `core/behavior`, `core/security-baseline`, `core/supply-chain` и `core/agent-safety` загружаются в каждой сессии.
2. **Правила стека подключаются по типу файла.** Редактирование `app/page.tsx` загружает `frontend/nextjs`, а редактирование `supabase/migrations/*.sql` — `data/supabase`. В инструментах без правил по файлам (Codex, Gemini CLI) каждое правило стека поставляется как навык `<stack>-conventions`, который загружается по запросу.
3. **Правило проверяет версию.** Агент читает lockfile и сообщает, что применяет, например:

   ```text
   Applying frontend/nextjs (next 16.4.1, react 19.2.8, from pnpm-lock.yaml).
   ```

4. **Ниже диапазона работают legacy-правила.** На Next.js 15 или с каталогом `pages/` агент следует `legacy/nextjs-pages-router` и `core/legacy-mode`.
5. **Навыки запускаются по запросу.** Процедуры вроде `security-audit`, `cve-check`, `upgrade-nextjs` или `migrate-cra-to-vite` не попадают в контекст, пока вы или агент их не вызовете, поэтому большая библиотека навыков почти ничего не стоит.

Более конкретные правила важнее общих, а правила безопасности важнее правил удобства, если вы явно не отменили их. В этом случае агент об этом скажет.

Все правила устроены одинаково: **Version check**, **Conventions**, **Security**, **Known vulnerabilities**, **Testing** и **Before you finish** — с точными командами линтера, проверки типов, тестов и аудита. Legacy-правила добавляют **Migration path**.

## Быстрый старт

Нужен Node.js 22 или новее. У скриптов нет зависимостей.

1. Склонируйте тег релиза:

   ```bash
   git clone --branch v1.1.0 https://github.com/Phaedra-Solutions/cursor-rules.git
   cd cursor-rules
   ```

2. Посмотрите, что пресет установит в ваш проект:

   ```bash
   node scripts/install.mjs --preset next-supabase --tool cursor,agents --dest ../my-app --dry-run
   ```

3. Установите:

   ```bash
   node scripts/install.mjs --preset next-supabase --tool cursor,agents --dest ../my-app
   ```

Параметры:

- `--preset`: один из [пресетов](#пресеты). Без него устанавливается всё.
- `--tool`: любые из `cursor`, `agents` (`AGENTS.md` и `.agents/skills/`) и `claude` (`CLAUDE.md` и `.claude/skills/`). По умолчанию `cursor,agents`.
- `--dry-run`: показывает каждое запланированное копирование, ничего не записывая. Запускайте сначала его.
- `--force`: перезаписывает отличающиеся файлы. Без этого флага скрипт ничего не записывает при любом конфликте. Если в проекте уже есть `CLAUDE.md`, добавьте в него строку `@AGENTS.md` вместо перезаписи.

Установщик записывает версию, пресет и хеш манифеста в `.cursor/rules/.cursor-rules-version` (или в `.agents/` или `.claude/`), так что всегда видно, какой релиз использует проект.

**Без клонирования:** скачайте архив для своего инструмента из [GitHub Release](https://github.com/Phaedra-Solutions/cursor-rules/releases), проверьте его по `SHA256SUMS` (`sha256sum -c SHA256SUMS --ignore-missing`) и скопируйте содержимое в корень проекта.

**Чтобы сначала посмотреть результат:** выполните `node scripts/build.mjs --preset <name>` и загляните в `dist/`.

Закрепите тег релиза и обновляйтесь осознанно; изменения перечислены в [CHANGELOG](../../CHANGELOG.md).

## Безопасность

Безопасность — часть каждого правила, а не отдельное дополнение.

- **Базовые правила, включённые всегда:**
  - `core/security-baseline`: безопасное программирование по категориям OWASP Top 10:2025 со ссылками на CWE Top 25.
  - `core/supply-chain`: никаких выдуманных пакетов, lockfile и фиксированные установки, минимальный возраст релиза, политика install-скриптов и закреплённые actions в CI.
  - `core/agent-safety`: полученный контент — это данные, а не инструкции; работа с секретами; подтверждение перед рискованными командами; списки разрешённых MCP-серверов.
  - `core/behavior`: точечные изменения и однострочные предупреждения о безопасности даже в коротких ответах.
- **Безопасность по стекам:** в каждом правиле есть раздел о безопасности и датированная таблица известных уязвимостей с минимальными безопасными версиями. Legacy-правила добавляют компенсирующие меры для версий, которые больше не получают исправлений.
- **Навыки безопасности:** `security-audit` (зависимости, код, секреты, контейнеры и CI), `dependency-vet` (проверка на тайпсквоттинг и выдуманные пакеты перед установкой), `cve-check` (поиск в OSV и GitHub Advisory), `secrets-scan` (gitleaks), `threat-model-lite` (10-минутный разбор по STRIDE) и `incident-supply-chain` (реагирование на скомпрометированную зависимость).
- **Для ваших проектов:** шаблоны CI в [`templates/ci/`](../../templates/ci/README.md) запускают OSV-Scanner, Semgrep, gitleaks и zizmor.
- **Для этого репозитория:** линтер pull request проверяет frontmatter, размер, скрытый Unicode, ссылки и Markdown. Ежедневная задача сверяет [`security/watchlist.yml`](../../security/watchlist.yml) с OSV и CISA KEV, а еженедельная проверяет каждый диапазон `applies_to` на новые релизы и даты окончания поддержки.
- **Сообщить об уязвимости:** см. [SECURITY.md](../../SECURITY.md). Не создавайте публичные issues об уязвимостях.

## Обновляйте инструменты

- **Cursor:** ряд исправлений 2026 года закрыл выход из песочницы и prompt injection (например CVE-2026-26268, CVE-2026-48124, CVE-2026-50548, CVE-2026-50549 и CVE-2026-73217). Используйте **Cursor 3.1.2 или новее** и устанавливайте обновления сразу после выхода. См. [бюллетени безопасности Cursor](https://github.com/cursor/cursor/security/advisories).
- **Claude Code, Codex, Copilot и другие агенты:** держите их на актуальных версиях; `core/agent-safety` охватывает их конфигурационные файлы и MCP-серверы.
- **Эти правила:** таблицы версий и уязвимостей устаревают. Обновляйтесь до последнего релиза хотя бы раз в месяц и используйте навык `cve-check`, прежде чем полагаться на таблицу.

## Частые вопросы

### Что такое правила Cursor?

Правила Cursor — это инструкции, которые ИИ-агент Cursor читает во время работы с вашим проектом. Правила проекта хранятся в `.cursor/rules/` в виде файлов `.mdc` с frontmatter, где указано, когда применяется правило: всегда, для определённых шаблонов файлов (`globs`) или когда агент решит, что описание подходит. Этот репозиторий генерирует такие файлы из одного источника вместе с `AGENTS.md` и Agent Skills для других инструментов.

### Нужен ли ещё файл `.cursorrules`?

Нет. `.cursorrules` — устаревший формат Cursor из одного файла. Текущие версии Cursor читают правила проекта из `.cursor/rules/*.mdc`, где каждое правило указывает, когда оно применяется, а также читают `AGENTS.md`. Установщик создаёт и то, и другое. Если в проекте ещё есть файл `.cursorrules`, перенесите всё нужное в правило проекта, а затем удалите файл, чтобы два набора инструкций не противоречили друг другу.

### Что такое AGENTS.md?

[`AGENTS.md`](https://agents.md) — открытый формат инструкций для ИИ-агентов, которые пишут код: обычный Markdown-файл в корне репозитория, который такие инструменты, как OpenAI Codex, GitHub Copilot, Gemini CLI и Cursor, читают перед началом работы. Его развивает Agentic AI Foundation при Linux Foundation. Этот репозиторий генерирует `AGENTS.md` с базовыми правилами, которые включены всегда, и указателем правил стека, а рекомендации для каждого стека поставляет в виде Agent Skills (`SKILL.md`), которые загружаются только при необходимости.

### Безопасно ли устанавливать файлы правил из интернета?

Относитесь к файлам правил как к коду: ваш агент выполняет то, что в них написано. В 2025 году исследователи показали, что невидимые символы Unicode могут скрывать вредоносные инструкции в файлах правил Cursor и Copilot (атака «Rules File Backdoor»). CI этого репозитория падает, если находит символы нулевой ширины, управляющие символы направления текста или символы-теги в любом текстовом файле под контролем git; каждый релиз публикуется с `SHA256SUMS`, а `--dry-run` показывает каждый файл, который установщик собирается записать, ещё до записи. Закрепите тег релиза и просматривайте diff перед обновлением.

### Чем правило отличается от навыка?

**Правило** — это короткая декларативная инструкция, которая должна быть в контексте каждый раз, когда редактируются подходящие файлы, например «используйте `proxy.ts`, а не `middleware.ts`» в Next.js 16. **Навык** — это пошаговая процедура, которая запускается по запросу, например «проверить зависимости» или «обновить Angular по одной мажорной версии за раз». До использования в контексте остаются только название и описание навыка.

### Работает ли это с Claude Code, Codex, GitHub Copilot или Gemini CLI?

Да. Устанавливайте с `--tool agents` для инструментов, читающих `AGENTS.md` и `.agents/skills/` (Codex, Copilot, Gemini CLI и другие), или с `--tool claude` для Claude Code — он получит `CLAUDE.md`, импортирующий `AGENTS.md`, и навыки в `.claude/skills/`. Можно установить сразу для нескольких инструментов: `--tool cursor,agents,claude`.

### Перезапишет ли установщик мои файлы?

Нет. Он никогда не перезаписывает отличающийся файл без `--force`, а при любом конфликте ничего не записывает. Сначала запустите `--dry-run`, чтобы увидеть все запланированные копирования.

### У меня старая версия. Помогут ли правила?

Да. Если установленная версия ниже диапазона правила, агент следует соответствующему правилу из `legacy/` и `core/legacy-mode`. Он вносит минимальные изменения, сообщает статус окончания поддержки, применяет компенсирующие меры для неисправленных CVE и предлагает навык миграции, например `migrate-angularjs`, `upgrade-express` или `migrate-dotnet-framework`. Он не мигрирует без вашей просьбы и спрашивает перед изменением любой версии, даже патча.

### Как правила остаются актуальными и точными?

У каждого утверждения о версии, дате или CVE есть источник во frontmatter правила. Ежедневная задача сверяет отслеживаемые пакеты с OSV и каталогом CISA Known Exploited Vulnerabilities, еженедельная отмечает правила, отставшие от новых релизов или дат окончания поддержки, а раз в месяц открывается issue с обзором безопасности. Для правил P0 есть наборы оценок, которые измеряют, насколько часто агент им следует.

### Можно ли добавить соглашения моей команды?

Да. Решения команды выносятся в слой в `conventions/`, который пресеты могут подключать; пример — [`conventions/phaedra.md`](../../conventions/phaedra.md). Общие правила уважают существующие решения проекта, поэтому в вашем слое нужно только то, что отличается для вашей команды.

### Как добавить стек, которого нет?

Следуйте [CONTRIBUTING.md](../../CONTRIBUTING.md) или используйте переиспользуемый промпт [`implementation-prompts/36-template-new-stack.md`](../../implementation-prompts/36-template-new-stack.md) со своим ИИ-агентом. Новые правила должны проходить `node scripts/lint-rules.mjs`.
